# 1～10 重构深度

深度是场景/构图变化的有序指导档位，不是相似度百分比、查重通过率、图像 API 的 strength/denoise 参数。相邻档位没有可保证的视觉距离；实际效果需看图。默认 10，可逐次指定；不自动改全局配置或根据平台查重猜分数。

| 档位 | 定义 | 可观察目标 |
|---|---|---|
| 1 | 轻微调整 | 保留主要场景、机位与布局，只微调环境光或次要背景 |
| 2 | 局部微调 | 主体布局保持，轻调配件位置、背景和光线 |
| 3 | 轻度重构 | 同类场景中更新台面/背景，适当调整机位或配件 |
| 4 | 适度重构 | 相近环境的新镜头，机位、商品摆放和环境材料有清楚变化 |
| 5 | 平衡重构 | 协调重设场景/背景、机位与布局，保留原有使用情境 |
| 6 | 明显重构 | 场景、机位、摆放与光线有明显变化，可更新真实操作动作 |
| 7 | 深度重构 | 新场景和空间布局，显著调整取景、光线及相关人物互动 |
| 8 | 全面重拍 | 原图主要作为商品依据，大部分可变场景和摄影选择重新设计 |
| 9 | 创意重构 | 在同一真实用途内选择新视觉叙事/操作时刻，减少继承原布局 |
| 10 | 最大重构 | 在用户允许范围内全面重新策划，所有未锁定维度均可重审，但不强求全改 |

## 档位不影响的商品约束

所有档位默认保留商品身份、款式、数量、图案、形状结构、原色、相对尺寸、包装、必要配件和原文案及其中的表情符号（emoji）。10 不等于允许更换产品、虚构卖点、删除配件或修改广告文字。用户对具体内容的明确修改要求优先，单纯调高深度不构成该授权。

锁定项优先于档位。例如“深度 8，但保留背景和机位”，只能在其余允许维度重构；不为了凑强度破坏锁定项。若可变范围不足，交付时说明实际限制。低档位允许轻微改动，不套用“必须大幅重构”措辞。

## 21 个可选维度

按参考图选择适用且协调的组合，不机械要求每档改几项，不把候选维度当作所有任务必须变化的清单。

1. 使用场景：改变地点，保留真实用途。
2. 背景空间：墙、门窗和家具的空间关系。
3. 桌面/承托材质：只调整环境，不能改变商品材质。
4. 装饰布局：季节元素或背景装饰的位置和密度。
5. 主商品排列：同一组商品的新摆放，计数不变。
6. 商品朝向：真实旋转或观察角度，不能镜像文字或重设计结构。
7. 配件布局：保持实物及数量，重设空间分布。
8. 人物所在方位：调整进入画面的方向，商品相对比例仍可信。
9. 操作动作：真实可行的使用姿势或操作时刻。
10. 衣着：适用时更换袖口、颜色和纹理，不强制新增人物。
11. 相机俯仰角：商品关键细节必须可读。
12. 相机拍摄方位：真实机位变化，不仅水平翻转。
13. 取景范围：近景/中景，不能裁掉必要商品。
14. 视觉重心：通过新取景改变主体组位置。
15. 留白位置：为文案与主体重新分配空间。
16. 主光源类型：窗光、漫射灯等符合场景的光源。
17. 光线方向：同步调整阴影与反射。
18. 环境配色：背景、衣物、台面配色；商品原色不改。
19. 景深层次：保持必要商品清楚，不以模糊替代场景变化。
20. 文案排版：可调整布局字号，默认文字与表情不改。
21. 人物样貌：对未锁定身份的场景人物，按深度协调调整脸型、五官组合、发型、发色、表情和气质；保留人物数量、合理解剖及真实使用关系。批次内存在人物时，性别构成目标为女性75%（可接受70%～80%）、男性25%（可接受20%～30%）；肤色按可见视觉色阶统计，目标为浅/白皙肤色70%、中棕肤色15%、深肤色15%。这是肤色外观分组，不推断种族或国籍。原图、角色关系或用户锁定项优先；小批次按最近目标分配，不为凑比例添加人物。默认使用成年人；确需未成年人时，必须有成人在同一画面中清晰陪同，禁止未成年人单独出镜。人物样貌不包含商品上的人脸、印花、雕像或玩偶图案。

### 人物样貌如何跟随深度

所有档位先遵守人物选角默认：不出现亚洲面孔；仅在用户提示词明确指定亚洲人物或要求保留具体人物身份时，对指定人物例外。此默认优先于低档位对未锁定场景人物的面部保留建议，不因原图有人脸或肤色配额而自动豁免。无人物、仅手部或背影时不补人脸，商品人脸/角色图案不适用选角规则。

- 1～2：以神态、表情和发型细节微调为主，保留可辨识的原有面部特征。
- 3～4：可调整发型、发色、妆容与气质，面部变化适度，避免无关的身份大幅替换。
- 5～6：对未锁定的场景人物，具体规划至少三项身份性面部变化，范围为脸型、眼型/眼距、眉形、鼻型、唇形、颌骨/颊骨。发型、服饰、妆容深浅和表情另行描述，不能计入面部变化数量；优先保留原有年龄段与使用角色。
- 7～8：为每位未锁定人物设计明显不同的虚构身份，逐人明确至少四项身份性面部变化（脸型、眼型/眼距、眉形、鼻型、唇形、颌骨/颊骨中选），并另外规划发型、神态、服饰和互动姿势。仅更换服饰、发色、妆容深浅或表情不算脸部身份重构。
- 9～10：重新选用不同的虚构面孔并整体设计人物组合；逐人写出至少四项身份性面部特征差异，再规划发型、神态和造型。保留人物角色、数量、真实用途与用户锁定项。

单张任务也要把该张人物写成具体档案。批次任务必须先按输出序号列出独立人物档案，并将对应档案写入每张实际提示词；不能只把人物差异留在批次说明或 `batch.json` 元数据中。场景参考图中的人仅作为姿态、角色和布局参考；用户未锁定身份时，明确要求不沿用参考人物面孔。不得把已生成的上一张/上一批人物图继续用作新人物的身份参考。

### 批次人物构成

统计单位是本批所有输出中可见的场景人物，不是图片张数。先按每张预计可见人物数计算整批目标，再把性别/肤色名额具体分配到逐张人物档案。女性目标75%（容许70%～80%），男性25%（20%～30%）；肤色视觉分组目标为浅/白皙70%、中棕15%、深肤色15%。例如10张、每张2人时，性别目标约15名女性和5名男性；不得为了方便而每张固定一女一男。输出人物不能因跨图重复计数而虚增比例。描述肤色时只写可见肤色，不将肤色当作种族、国籍或文化背景的替代判断。单张或人数过少时，采用最接近目标的自然安排并记录实际计数，不编造人物填满配额。无人参考图不因比例要求加人；明确身份、性别、肤色、人物数量或关系的用户锁定项优先。

人物以成年人为默认。只有原图内容或用户明确需要未成年人时才安排未成年人，且必须在同一画面中出现一名可辨识的成年陪同者；未成年人不得单独出镜，也不得只用画外成人暗示陪同。不得把成人画成儿童，也不凭面孔推断精确年龄。

用户要求保留某个人的身份/样貌，或任务本身以该人物肖像为主要展示对象时，保留身份，仅调整允许的神态与造型。商品本体的人脸、印花和角色图案始终按商品保真处理，不适用人物换脸。只有手部或背影时只处理可见部分，不补出面孔；无人物时本维度不适用，不因此新增人物。上述变化属于提示词规划，不保证模型精确保留或替换身份，不代表平台查重效果。

### 人物表情也随深度变化

表情属于第21项人物样貌重构的独立计划，不新增一个用户必填参数。默认保留原图的情绪基调，深度只控制同一基调内的表情变化幅度。深度越高，可调整的视线、眉眼、嘴部及表情时刻越多，不改变情绪方向，也不等于笑得越大或越夸张。只有用户明确要求改变情绪方向时才覆盖此默认规则。

| 深度 | 表情变化目标 |
|---|---|
| 1～2 | 保持原有情绪，微调视线、眼神、眼睑和嘴角，形成轻微的抓拍差异 |
| 3～4 | 在相同情绪基调内做可见变化，例如原图微笑时调整笑意与眉眼组合 |
| 5～6 | 在同一基调内根据动作设计自然表情，例如从看镜头微笑改为看向商品微笑 |
| 7～8 | 随新场景与互动扩大同一基调内的变化，例如从对镜头浅笑改为与同伴相视而笑；不切换情绪方向 |
| 9～10 | 在原情绪基调内充分重设表情、视线与反应组合；原图笑就设计不同自然笑容，不因深度10改成哭泣、悲伤或愤怒，也不强制大笑/惊讶 |

Agent 看图后在 `human_presence` 中写明原表情、原情绪基调、同基调的目标表情和具体变化；同时写明批次目标人数/性别/肤色计数，以及每位未锁定人物按深度计划的外貌变化项。看不清情绪时记录可见依据与不确定性，保守调整，不能强行猜成另一种情绪；若用户明确要求改变情绪方向，另行记录该要求，再据此规划目标表情，在 `planned_changes` 中体现适用的表情计划；不要只写“表情不同”。无需用户逐项指定。用户锁定某个表情或情绪时优先保留。仅要求“保留同一个人/长相”不自动锁定表情，可保留身份并按深度改变神态。商品上的角色表情与广告 emoji 继续保留，只有手部/背影或无人时本项不适用，不新增人脸。

## 如何使用

用户直接上传图片并写 `7` 即可；也可说 `$pinshuai-image 7` 或“重构深度7”。新任务没写深度默认 10，不要求用户选择变化维度。具体变化由 Agent 根据图片和档位自动策划。解析数量、任务续接及付费边界按 SKILL.md 的“用户只需给图和一个数字”执行。

Agent 先依据档位和锁定项填写实际场景、布局等字段，再在 JSON 中写入：

```json
{
  "reconstruction": {
    "level": 7,
    "locked_dimensions": ["商品、配件和文案内容"],
    "planned_changes": ["明确的新场景", "明确的新机位", "明确的新摆放"]
  }
}
```

以上只是结构片段，必须和完整商品清单、场景计划合并后运行。`--depth 7` 与 JSON 的 level 必须一致；冲突时入口拒绝请求，先根据真实用户选择调整计划，不盲目以一个数字覆盖已写好的高强度场景。未指定 CLI 参数时使用提示词 level，再否则默认 10。旧提示词不自动理解自然语言强度，Agent 仍需按选定档位重新整理具体内容。

宿主出图/仅提示词模式使用相同档位定义，在最终提示词里给出档位含义、计划与不变量；不能只传一个数字。交付报告目标档位和实际可见变化，不给输出编造精确“实测深度”。
